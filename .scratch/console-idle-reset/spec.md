# 控制台也自動清場並返回主數位人

Status: implementation-complete

日期：2026-10-29。使用者回報天氣助手不會清資料、清對話及自動返回。
執行中 API 僅有控制台對話；舞台設定為 15 秒清畫面、60 秒完整重置。
使用者明確回答「是，控制台也自動清場並返回」，授權兩端套用同樣的
清場規則。這修訂 ADR-0020 原先控制台保留對話、自動清場僅屬舞台的範圍。

## 已確認行為

- 控制台與舞台各自依既有清場秒數倒數，預設 15 秒清畫面、60 秒清空
  本場所有角色記憶、附件與草稿，再返回主數位人；主角色與天氣助手
  都適用。清畫面時保留記憶與附件，完整清空才返回。
- 上傳、分析、回答與轉場期間不清場；有新互動則重算。兩端獨立，
  一端清場不取消另一端的回答或刪除另一端的資料。
- 完整重置保留連線、語系及收音意圖，並採用下一場對話的新預設。
  閒置招呼仍只在舞台播放；既有人工清空／返回語意保持不變。
- 對話記憶面板顯示該場有效時間；停用自動重置時不冒稱仍有清場倒數。

## 重現與修正

先驗證舞台的主／天氣角色及完成天氣交接後的自然播放流程，均能清場。
同一測試切到控制台後，倒數工作完全不存在，與使用者回報相符；舊
測試甚至明確要求控制台永不自動重置。確認新需求後，先加入控制台
失敗案例，再移除兩處僅舞台的計時／返回限制，修正 API 時間及 UI 說明。

聚焦 Python：139 passed；聚焦 Web：32 passed。涵蓋兩端主／天氣
角色、自然播放結束、短清畫面保留資料、完整清空返回、保留另一場
進行中的回答、停用時間 metadata 及實際記憶面板渲染。
