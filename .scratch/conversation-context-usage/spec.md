Status: 使用者已接受整體設計；功能已實作，場次隔離與瀏覽器驗收通過。

更新日期：2026-10-27。

## 已確認需求

- 控制台新增最大 context 與使用量顯示。
- 使用者需要知道同一場對話中，LLM 可容納多少記憶，以及目前用了多少。

- Q2 已確認：先顯示用量，保留按訊息數量限制歷史的策略；本次不擴充為按 context 容量保留全部對話，也不新增摘要記憶。
- Q7 已確認主畫面建議，並追加「歷史訊息保留上限可在控制台修改」；預設維持目前 20 則。
- Q8 已確認：控制台可選自己的對話或某個已連線舞台，顯示該場記憶並控制該場語系／聲音；另設新對話預設。
- Q9 已確認：保留目前舞台閒置清空設定與可設定機制，並在記憶資訊旁顯示清空時間。
- Q14 已確認：使用者與助手歷史訊息各算一則；可暫時修改目前選定場次的保留上限，也可另存為新對話預設，不影響其他既有場次。
- Q15 已確認：調低上限時若閒置就淘汰最早訊息，輪次進行中則等該輪結束再套用；調高不復原已淘汰內容。
- Q16 已確認：請求超過 context 時保留既有記憶並明確提示容量不足，可由管理者降低保留上限或清空；維持按訊息數保留策略，不默默改用摘要或 token 淘汰。

## 訪談時查證現況（實作前）

- `src/llm/service.py` 的 `llm_response()` 為各個 session 建立獨立 LLM 實例，建立時指定 `max_history=10`。
- `src/llm/history.py` 的 `TransactionalHistory` 以 `max_turns * 2` 限制訊息筆數；目前並非依 token 預算保留歷史。若輪次沒有已播回覆，使用者訊息仍可能單獨提交，因此「10 輪」不是所有情況下的精確完整輪數。
- 依既有輪次提交契約，已播回覆與已顯示看板各有提交邊界；用量顯示必須考慮實際提供給模型的請求內容。
- 模型宣稱的容量、部署實際啟用的容量、請求用量及歷史保留限制需要分別確認，不能以同一數字代稱。
- 2026-10-27 唯讀查詢：本機服務各 slot 回報實際 context 為 8,192 tokens，模型 metadata 回報訓練 context 為 131,072 tokens；兩者不同。這是當時部署觀測值，功能不可硬編碼此數字。
- 現有請求未收集 streaming usage，沒有 token 預檢、超量自動縮減或摘要；數值顯示需補足量測來源，不能假裝現況已有精確用量。
- 對話記憶另受舞台閒置清空機制影響；當時 runtime 設定為 3 秒，控制台對話不套用此舞台閒置機制。Q9 已確認保留此清空邊界與可設定機制。
- 已顯示看板上下文獨立於 20 則歷史訊息限制，系統提示與檢索參考也占 context，不能將 20 則直接換算成固定 token 上限。

## 第一輪訪談

### Q1：用量定義

使用者澄清重點為同一場對話可保持多少對話內容。主要呈現目前保留的對話數量、歷史保留上限與最早可參考的輪次，context 用量作為補充。具體呈現已由 Q7 確認。

原先提議的總輸入用量涵蓋系統提示、回覆規則、檢索參考、對話歷史及本輪問題；這些內容不能全都標成「對話記憶」。量測精度與更新時機待查證後確認。

### Q2：是否擴充記憶

已確認：第一版新增用量與容量提醒，維持按訊息數保留的策略。Q7 後續追加保留上限可調整，因此「保留策略」不代表固定鎖死 20 則。

## 顯示與量測契約

- 歷史訊息數只計供後續回答參考的使用者與助手訊息；已顯示看板、系統提示、規則與檢索參考的 context 占用另行呈現。
- Context 的分母使用部署實際可用容量，不能以模型宣稱的理論上限代替；查不到時標示未知，不顯示虛構百分比。
- 量測值與估算值分開標示；最近一次請求的觀測結果須與目前已保留歷史的數量區分，避免把累計 token 或過時結果標成即時記憶。
- 輪次提交、淘汰、清空或切換檢視場次後更新記憶資訊；舞台閒置清空時顯示清空狀態，不繼續顯示先前保留數量。

## 驗收案例

- 歷史達設定上限後可指出最早保留內容與淘汰狀態；不將所有控制台紀錄宣稱為仍在記憶。
- 控制台修改 A 場次上限或新對話預設，不改變 B 場次現有設定。
- 進行中調低上限不改寫該輪請求；輪次結束後數量符合新上限。再次調高不會恢復已淘汰內容。
- 模型容量未知或量測失敗時仍能顯示實際保留訊息數，未知或估算欄位有明確標示。
- 請求超過可用 context 時，保留既有對話記憶並提供可採取的處理方式。
- 舞台依現有閒置設定清空時，記憶數量與清空狀態同步更新。

- 控制台顯示目前保留則數、上限、最早保留內容及移出則數，並可選場次調整上限，或另存新對話預設。預設 20 則，合法範圍 1–2,000；調高不恢復舊訊息，調低等待目前輪次完成。另可清空選定場次的記憶與看板：先停止該場舊回答，其他場次不受影響，原本暫停收音者維持暫停。
