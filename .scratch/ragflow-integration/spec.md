# RAGFlow 檢索整合規格

Status: 已確認（2026-09-16）

## 目標

在目前主機部署獨立的 RAGFlow，供 Nova Avatar 檢索管理者上傳的文件。RAGFlow 不產生數位人的最終回答；現有模型、回覆規則、看板、語音與輪次提交契約保持權威。

## 使用者行為

- 控制台新增 RAG 設定：顯示連線狀態、目前數位人的啟用狀態與知識庫選擇，並可輸入測試問題檢查檢索結果。
- 每個數位人各自保存啟用狀態與知識庫選擇。首次安裝預設關閉；新數位人未設定時也預設關閉。
- 此設定只隔開各角色的回答資料來源，不充當使用者存取權限；若未來有私密知識庫，需另設控制台與 API 的授權規則。
- 管理者在僅限本機存取的 RAGFlow 原生介面建立知識庫、上傳及解析文件。Nova 控制台不複製文件管理介面。
- 語音與文字發問都依目前數位人的設定檢索。檢索成功時，把有界的相關內容作為本輪模型回答參考；控制台列出檢索參考，但不把它當成正式引文、已播回覆或看板項目。
- 無相關內容時，模型可一般回答，但口語回答與控制台都須明確標明沒有文件依據。RAGFlow 無法連線或逾時時，原本回答流程繼續，控制台顯示檢索失敗。
- 切換數位人、取消輪次或清空對話時，不得沿用舊角色或舊輪次的檢索結果。

## 部署與資料邊界

- 使用固定的 RAGFlow 穩定版本，獨立 Docker Compose 專案、網路、資料卷及啟停流程；完成本機準備後，由 `start-all.sh` 協調啟動，只停止本次由它帶起的服務。
- RAGFlow 網頁與 API 只綁定主機 loopback。MySQL、文件索引、物件儲存、快取不對主機公開連接埠，也不共用 Nova 的資料庫。依 2026-09-16 安裝時的使用者補充，嵌入程序沿用主機現有 Ollama 程式與模型檔，但使用獨立 CPU 程序及 Docker 本機橋接埠；Nova 原有 Ollama 與 llama.cpp 語言模型設定不變。
- RAGFlow 的 API 位址與金鑰留在後端環境設定；金鑰不寫入 `runtime_overrides.yaml`，不回傳瀏覽器。控制台只儲存每位數位人的非機密設定。
- 文件與查詢不送往外部嵌入 API。建議在 RAGFlow 專屬服務中使用本機 BGE-M3 嵌入模型，以支援中英混合文件；此模型及其授權須在首次建立知識庫前確認。
- 對檢索逾時、片段數量、片段總長度與文件解析並行量設定上限。檢索內容視為不受信任資料，不得覆寫現有系統規則。
- 實機測試顯示 CPU BGE-M3 檢索可能超過原訂 2.5 秒，因此已將啟用 RAG 時的總逾時調整為 8 秒；未啟用時沒有這段等待。

## 驗收

- RAG 關閉、RAGFlow 停止或沒有設定知識庫時，現有語音、文字、模型規則、看板及字幕流程通過既有回歸驗證。
- 測試文件可在 RAGFlow 原生介面完成解析，控制台能選到其知識庫並顯示檢索結果；語音與文字各完成一輪有依據的回答。
- 無命中、服務中斷、逾時、角色切換、插話與輪次取消均不留下舊輪次檢索內容，也不把未播回答寫入歷史。
- RAGFlow 管理介面、API 與依賴服務符合本機存取邊界；金鑰不出現在控制台回應、日誌或版本庫。
- 測量 Nova 對話在 RAG 關閉、RAG 開啟及文件解析期間的延遲與資源使用；若與既有功能的效能要求衝突，先調整資源限制與解析排程，不宣稱已達成隔離。
- 完成 `uv run python scripts/check-integration.py`、`uv run pytest`、`cd web && npm test`、`cd web && npm run build`。

## 部署前的人工步驟

Docker 與 Compose 已在目前主機就緒，獨立的 RAGFlow 服務與 BGE-M3 嵌入端點也已啟動。RAGFlow 首次帳號建立、嵌入模型供應者設定、知識庫匯入與 API 金鑰取得仍需在本機管理介面完成。不要在對話中傳送密碼或金鑰。
