# 數位人角色交接與即時天氣

Status: implementing

使用者已確認 Q1–Q27、完整規格並明確要求開始實作。核心實作與自動回歸已完成，雙角色長測持續驗證。CWA 有效授權碼與雙端交接實測結果見本目錄 JSON；以下效能數字仍為驗收目標，不能以伺服器事件代替瀏覽器觀看端驗收。

## 已確認的首版範圍

- 可建立多份數位人設定檔，當次選定主數位人、專門數位人各一份。
- 設定檔各自保存身分／限制 Prompt、輸出語系、禁止自稱名稱、人物素材、LLM、RAG 知識範圍、聲音與回覆規則。同一人物素材可供多份設定檔引用；舞台背景共用並獨立選擇。
- 控制台預覽與舞台同步作用中角色，對話紀錄各自保留；每個訪客／測試會話內再依設定檔分隔角色記憶。
- 主數位人依可編輯的交接規則與專門角色介紹，由其 LLM 判斷是否交接。接手主題可設定，首版以天氣驗收；語意不清時先詢問。
- 主數位人播完可編輯的固定交接說明後，才經轉場換角色。專門角色承接原問題與必要的已確認地點、日期等上下文。
- 內建淡入淡出、左右滑動、縮放，作用於人物層；自訂影片覆蓋舞台，首版靜音。來源→目的各自保存轉場，返回影片獨立設定。
- 舞台與控制台僅在專門角色作用中顯示返回按鈕。人工返回立即停止剩餘回答、只提交已播內容、轉場回主角色並保留本訪客各角色記憶。
- 轉場開始清除舞台字幕與看板；返回不重顯示舊答案。控制台保留可按角色查看的紀錄。
- 專門角色收到非專長問題時提示可返回，不自動反向交接；混合主題先詢問優先主題。
- 交接說明中可插話取消；轉場中暫停收音及重複切換。目標角色準備失敗留在主角色；天氣 API 失敗明說暫時查不到最新資料。
- 舞台閒置訪客對話重置清除該訪客各角色記憶，並轉場回主角色；不清除控制台測試紀錄。
- 首版採 CWA、支援臺灣，包含即時天氣資料查詢；控制台設定場域預設縣市／鄉鎮。回答明示查詢地點；臨時地點只保存於本訪客對話。
- 驗收組合：主角色 `musetalk_angela`、專門角色 `musetalk_1`，共用 `Qwen3.5-9B-UD-Q4_K_XL` 與 MuseTalk 推理模型；各自套用設定檔。
- 「保存設定」只包含目前設定，沒有設定版本歷程／還原需求。原始麥克風音訊延續預設不持久保存的契約。

## 互動與角色切換

正常路徑：

```text
主角色待命 → 收到問題 → 判斷／必要時澄清 → 目標角色準備就緒
  → 主角色交接說明 → 說明語音結束 → A→B 轉場
  → 專門角色回答原問題 → 專門角色待命
  → [人工返回] 停止剩餘回答／提交已播內容 → B→A 轉場 → 主角色待命
```

- 角色、媒體與輪次的切換由伺服器編排；前端不重送訪客問題來觸發專門角色回答。交接控制資料經明確資料通道處理，不進入語音、字幕、看板或歷史。
- 切換保留既有 WebRTC 連線及 track、麥克風授權；跨角色素材使用共同舞台輸出規格。背景保持原選擇。
- 準備期間維持來源角色畫面。交接說明未完整送出或輪次失效時，取消交接，保留已播內容；取消的 envelope 不能被當成「說明成功播完」。
- 角色轉場完成前，目的角色語音不得送出。影片只播一次，結束時切到目的角色；影片載入／解碼失敗時使用內建淡入淡出，已接受的原問題只交付一次。
- 轉場失敗且目的角色無法呈現時回來源角色，恢復收音並顯示可理解的失敗訊息。取消／失敗後的舊 LLM、RAG、天氣、TTS 與影格不得流入新角色。
- 返回不再次提交或重答先前的原問題。為原問題建立交接識別，來源交接與目的回答可在控制台對應；歷史仍分屬各角色。
- 沒有為返回流程新增口述說明的需求；返回以所設定的視覺轉場進行。

## 天氣資料與來源事實

官方 API 與產品查證見[研究紀錄](weather-api-research.md)。本節是官方能力邊界，第四輪 Q25 再決定首版對外提供的欄位。

- CWA 觀測 `O-A0003-001` 每 10 分更新，時間欄位 `ObsTime/DateTime` 是觀測時間；測站資料須標站名及觀測時間。[觀測目錄](https://data.gov.tw/dataset/9178)、[觀測標準](https://opendata.cwa.gov.tw/opendatadoc/Observation/O-A0003-001.pdf)
- 鄉鎮產品提供 3 天及一週預報，發布時間為每日 05:30、11:30、17:30、23:30，可能追加更新；前三天與一週產品的時間粒度不同。**一週產品的降雨機率只提供前三天**，第 4–7 天應標示未提供，不能補成 0。[官方產品說明](https://opendata.cwa.gov.tw/opendatadoc/Forecast/F-D0047-001_093.pdf)
- `/api/v1/rest/datastore/F-D0047-093` 的 `locationId` 必填，支援 1–5 個產品代碼；同一鄉鎮可查其縣市的三天及一週產品。例如臺北市為 `F-D0047-061`、`F-D0047-063`，地名參數為 `LocationName`。目前官方 Swagger 已宣告此介面，但混合產品的實際 JSON 回傳尚未以金鑰驗證；實作先驗證各縣市直接端點。[官方 Swagger](https://opendata.cwa.gov.tw/apidoc/v1)
- 溫度、降雨機率等欄位依來源時點／區間回答，區分來源發布時間、觀測時間、預報有效區間及系統取得時間。JSON 未帶發布時間時保留未知，不能以取得時間冒充。
- 機率以來源區間表達，不將 12 小時或 3 小時機率混稱逐時機率；缺值、儀器異常及超出可用範圍均不得送入數值聚合或由模型補數字。
- API 結果作為本輪結構化事實交給目前角色的 LLM；RAG 用於解說背景知識，沒有命中文件的一般回答回退不適用於最新天氣數值。失敗時依已確認契約說明查不到最新資料。
- 地點優先序：訪客本輪明確指定 → 本訪客已確認的相關地點 → 場域預設地點。地名有歧義時先詢問；沒有配置預設地點也未提供地點時先詢問，不能沿用研究測試的臺北座標。
- 臺灣相對日期以 `Asia/Taipei` 解讀；在發話／交接時確定查詢日期，跨午夜仍使用同一份已確定查詢。訪客更正日期或地點會建立新的有效查詢。
- CWA 授權碼由服務端環境載入，不列入可匯出的角色設定、一般 API 回應或日誌；回應顯示資料來源與資料時間。[授權碼使用方式](https://opendata.cwa.gov.tw/devManual/description)、[資料授權](https://data.gov.tw/license)

## 設定與遷移規劃

- 設定檔使用獨立穩定 ID，引用既有 `avatar_id`；名稱與人物素材不作為訪客記憶或 RAG 設定的唯一識別。角色轉場以來源、目的設定檔 ID 配對。
- 新增設定存放與既有全域 runtime 設定相容：首次遷移將有效助手、模型、聲音、回覆規則及對應 avatar 的 RAG 引用複製至主角色，保留原檔及遷移標記，重啟不覆蓋後來修改的設定檔。
- 天氣角色以新的設定檔建立，選 `musetalk_1`，在控制台保存其 Prompt／RAG／聲音；不直接把主角色的身分及知識庫套給它。
- 未開啟角色交接功能時保留既有單角色運作方式；這是回復路徑，並非宣稱既有 `/api/avatar` 已支援不斷線切換。
- 對外保存目前值及 revision，避免兩個控制台覆蓋彼此的設定；進行中輪次持有一致的角色／規則／RAG／模型快照。
- 素材上傳、發布、查找及刪除沿用伺服器命名、有界讀取與失敗清理原則；轉場影片建立自己的驗證契約。現有背景影片只驗首幀且未去除音軌，不能直接視作通過轉場驗證。

## 第四輪已確認

使用者已全部採用以下方案。

| 問題 | 建議方案 |
| --- | --- |
| Q23：兩端輸入協調 | 舞台連線後預設訪客模式，由舞台接收問題；控制台仍可人工返回／停止。獨立測試前由控制台明確切到測試模式，舞台暫停收音與閒置重置計時、保留連線及記憶；同時只接受一個輸入來源。模式切換等目前輪次結束，需提前停止時使用既有中斷／返回。舞台斷線時可由控制台測試，舞台重連回訪客模式，結束測試後重新開始訪客閒置計時。 |
| Q24：即時組合與延遲目標 | 首版即時組合限定共用同一 MuseTalk 推理模型及同一 LLM 服務／模型；其他模型選擇可保存，組合不相容時先阻止啟用並解釋原因。共用推理模型、預載兩角色素材；目標為內建轉場結束後，使用有效快取的天氣回答首音 p95 ≤ 2 秒；需要新查詢時查詢總預算 3 秒，超時走明確失敗回覆。這些是實作驗收目標，尚非已測得成績。 |
| Q25：天氣欄位與新鮮度 | 提供目前觀測、今天／明天／未來七天基本預報，含溫度／天氣、來源有提供的體感溫度與降雨機率；機率只在來源提供的前三天回答。觀測快取 5 分鐘、資料觀測時間超過 30 分鐘視為過舊；預報快取 10 分鐘，檢查所問有效區間，來源發布時間可得時超過 8 小時視為過舊。發布時間無法取得時明示未知，不能宣稱最新一報；缺值／逾時不以模型猜測。以上 TTL／年齡門檻屬本系統政策，不是 CWA 保證。 |
| Q26：轉場媒體契約 | 接受 MP4／MOV／WebM，100 MiB、30 秒內；完整驗證並轉為靜音、25 fps 的 MP4。首版共同輸出 720×1280，人物等比縮放，影片等比完整置入、空白以場景填滿，不拉伸。內建特效預設 0.6 秒，可設 0.2–2 秒；沒有該方向影片設定時預設淡入淡出。素材解碼使用有界緩衝，不將整段原始影格載入記憶體。 |
| Q27：重啟、修改、刪除 | 保存當次角色組合及轉場，重啟從主角色開始；訪客記憶不跨程序重啟。儲存設定與套用分開，已開始輪次保留舊快照，套用等輸入／輸出輪次及轉場結束。身分／LLM／RAG 範圍改動只清該設定檔的記憶及看板；聲音／回覆規則改動保留。當次組合中的角色或被轉場引用的影片須先解除使用再刪除；刪設定檔不連帶刪人物素材。 |

## 實作責任與測試

- 角色設定檔／遷移：保存與驗證、revision、角色 RAG 引用、角色／會話記憶隔離，依 Q27 套用與清除。
- 角色交接編排：主 LLM 明確控制結果、交接原問題、音訊完成柵欄、轉場狀態機、單次交付、取消／失敗恢復及 Q23 輸入協調。
- 角色素材與呈現：共用 MuseTalk／LLM 模型、雙素材預載、固定輸出、人物層特效、影片上傳正規化、控制台與舞台狀態同步。
- 天氣服務：CWA 授權碼、縣市鄉鎮映射、日期／區間、觀測與三天／一週產品轉換、缺值、時間／來源、快取、逾時及輪次取消。
- 控制台與舞台：設定檔、主／專門角色組合、定向轉場編輯、交接規則／文案、場域地點、返回按鈕、對話紀錄與就緒／失敗狀態。

| 驗收情境 | 必須觀察到的結果 |
| --- | --- |
| 主角色問「明天臺北中正區會下雨嗎」 | 主角色先完整說明；之後轉場，天氣角色只回答一次原問題，資料地點／日期／機率區間正確。 |
| 前文已確認地點後問「那明天呢」 | 交接帶必要已確認上下文，專門角色使用自己的 Prompt／RAG／記憶。 |
| 插話取消交接說明／重複切換／影片中輸入 | 按既定契約處理，舊文字、音訊、影格或查詢結果零外漏，恢復後下一輪可正常回答。 |
| 專門角色回答中按返回／閒置重置 | 前者只提交已播內容並保留各角色記憶；後者清本訪客全部角色記憶。按鈕顯示條件正確。 |
| A→B 自訂片、B→A 內建特效 | 使用各自設定；背景不隨角色變更；影片只播一次、無音軌，失敗回退可用。 |
| 控制台與舞台同時連線 | 同一作用中角色與轉場；依 Q23 唯一輸入來源；對話記錄不混用，無隱藏 WebRTC 重連。 |
| 一週預報第 4–7 天降雨機率 | 表達未提供，不能回 0%、猜測機率或將早期區間當成整週機率。 |
| 同名地點、超出範圍、缺值、時間過舊、401／429／逾時 | 先澄清或說明無法取得所需最新資料；控制台有可理解狀態，之後有效輪次可恢復。 |
| 同素材不同設定檔／修改一份設定／程序重啟 | 設定、知識範圍及記憶隔離；原設定遷移不反覆覆寫；重啟回主角色。 |

驗證分層：先做有意義的設定／狀態機／CWA adapter 測試，再做雙角色真實 WebRTC soak（舞台、控制台各至少 50 輪）。效能記錄分開計算發話結束→交接首音、說明最後音訊→轉場、轉場時長、轉場完成→專門回答首音、外部 API 延遲、插話恢復、RAM／VRAM 峰值與 A/V 配對偏移；不把交接說明或等待文案當作專門回答首音。

程式現有片段結束事件只代表伺服器交付 WebRTC sender，沒有瀏覽器已聽完 ACK。實作需讓轉場服從有效媒體時間軸，並以真實觀看端的聲音／畫面順序驗收；伺服器事件與 RTP 指標不能單獨替代瀏覽器 A/V 檢查。沒有可用瀏覽器或 CWA 授權碼時，須分開列出完成的自動驗證與尚未完成的實機驗收。

功能交付前完成專案要求的 integration／rebranding audit、完整 Python／web 測試及 web build；不得用文件與匿名 Open-Meteo 測試結果宣稱 CWA 或雙角色功能已通過。
