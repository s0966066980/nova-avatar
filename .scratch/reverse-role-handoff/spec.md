# 專門數位人自動交回主數位人

Status: implementation-complete

日期：2026-10-29。使用者指定 `grill-with-docs`，結合 `grilling` 與
`domain-modeling` 逐輪釐清需求。使用者已以「根據建議」接受重新提問的
Q1–Q3，並以「開始實做」確認完整共同理解、授權實作；後續「繼續」維持
此授權。完整規格如下。

## 使用者需求

目前在天氣助手時，只要問了天氣以外的問題，就自動切換回主數位人，
如同主數位人遇到天氣問題會自動交給天氣助手。天氣助手是目前的專門
數位人驗收案例。

## 已確認決策

- 使用者於第一輪後更正：觸發條件是「天氣以外的問題」，不要求訪客
  明確說出返回或主數位人，也不以問題是否落在主數位人的已知專長為
  額外門檻。主數位人切回後仍遵守自己的身分、知識與回答限制。
- 本次不以「只有要求返回、沒有問題」作為主要設計情境；既有人工
  返回行為繼續保留。
- Q1：天氣助手先播交接說明、播放既有返回轉場，再由主數位人直接
  接續回答原本的非天氣問題，訪客不用重新提問。
- Q2：天氣相關生活建議及依前文判斷的天氣追問，繼續留在天氣助手。
  例如「明天適合爬山嗎？」與天氣話題下的「那週末呢？」。
- Q3：同一句同時包含天氣及非天氣主題時，先確認優先主題，再依確認
  的主題決定是否交接；不在尚未釐清時自行來回切換。

## 完整行為與現有邊界

- 語音與文字輸入共用同一語意判斷，依目前問題及已確認上下文區分
  天氣、非天氣與需要釐清；沿用現有 LLM 交接判斷方式。
- 天氣以外的問題會交回主數位人；主數位人依自己的身分、知識範圍、
  回答限制與記憶回答，無法回答時仍應如實說明。
- 反向交接沿用正向交接體驗：主數位人就緒後，天氣助手先播固定的
  交接說明，再播放已設定的天氣助手→主數位人轉場，最後交付新問題。
  反向說明沿用可編輯中文／英文固定文案方式，提供可用預設。
- 一次交接的原問題只交付一次，目的角色接續時跳過重新路由，避免
  同一題在兩角色間反覆切換。之後的新問題可重新判斷方向。
- 各角色的完整記憶與 RAG 範圍繼續隔離；只交付原問題與必要、已確認
  的交接上下文，保留本場語系、已選附件與各角色記憶。
- 保留目標能力檢查、來源角色失敗恢復、交接說明中插話取消與轉場中
  暫停收音及重複切換的現有規則；已取消的舊交接不能在之後自行完成。
- 控制台與舞台各自切換，互不干擾；既有人工返回、閒置完整重置與
  正向天氣交接繼續適用各自的行為。

## 驗收情境

| 情境 | 預期行為 |
| --- | --- |
| 天氣助手收到「介紹你們的服務」 | 播反向說明及返回轉場，主數位人回答同一問題一次 |
| 非天氣問題超出主數位人的知識範圍 | 仍切回，由主數位人依自己的回答限制說明 |
| 天氣助手收到「明天台北會下雨嗎？」 | 天氣助手繼續回答，不切換 |
| 天氣助手收到「明天適合爬山嗎？」 | 作為天氣相關建議留在天氣助手，缺少必要資訊則先詢問 |
| 天氣話題下問「那週末呢？」 | 沿用已確認的地點及天氣話題追問，不因省略天氣字詞而切換 |
| 「明天天氣如何？也介紹一下你們的服務」 | 先詢問優先主題；確認後依該主題回答或交接 |
| 反向交接完成後又收到新的天氣問題 | 沿用既有正向交接，可再交給天氣助手 |
| 交接說明尚未完成就插話／取消 | 取消該次交接，晚到結果不會切換角色或重答 |
| 目的角色或附件能力不符、轉場失敗 | 沿用現有檢查及恢復契約，不混用角色身分或遺失原問題 |
| 控制台與舞台同時對話 | 只切換收到問題的那一場，不取消另一場輪次 |
| 按既有人工返回按鈕 | 停止目前回答、轉場並等待下一次輸入，不重答舊問題 |

實作時先補路由與交接接續回歸，涵蓋雙向交付、混合主題釐清、取消、
失敗及雙場隔離；交付前完成專案完整 Python／Web 驗證與品牌授權稽核。
自動化與真人麥克風／喇叭、轉場實機結果分別記錄。

## 實作前已查證事實

- 現行規格明定專門角色收到非專長問題只提示返回、不自動反向交接；
  本需求將修訂此限制。見[原規格](../live-avatar-switch/spec.md)。
- `src/profiles/routing.py` 明文禁止自動反向交接；路由僅有
  `answer / specialist / clarify`，目前未提供主角色的介紹供反向判斷。
- `src/profiles/coordinator.py` 的交接完成目標，以及
  `src/server/voice_session.py` 的內部接續資格目前固定為專門角色。
  現有人工返回只切回主角色，沒有交接說明及原問題接續回答。
- 反方向的視覺轉場已可獨立設定；設定介面目前只有正向的判斷規則與
  中英文固定交接說明。目的角色接續原問題時跳過重新路由一次。
- [ADR-0016](../../docs/adr/0016-isolate-avatar-profiles-and-visitor-memory.md)
  的每角色記憶隔離與明確交付原問題，以及
  [ADR-0020](../../docs/adr/0020-independent-console-and-stage-conversations.md)
  的控制台／舞台各自切換，繼續作為現有邊界。
