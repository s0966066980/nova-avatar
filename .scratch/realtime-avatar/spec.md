# 數字人延遲改善與無 LLM 驗證

使用者要求先不使用 LLM，以固定回答確認數字人能即時生成，並分析
可改善的延遲。測試需包含實際模型與媒體傳輸，不能以假嘴型或只量
音訊播放掩蓋生成不足。

單一 Jetson 會話驗收：所有 PCM 完整送出，播放長度接近原音訊；
標記 PCM 最大間隔小於 60ms、A/V 首次釋放偏差 P95 不超過 80ms，
嘴型覆蓋率至少 95%，PCM 就緒到首音不超過一秒。
近似解碼器需明確選用、揭露畫質取捨，原路徑維持可用。
不能移除上游授權、放寬既有全解析度效能測試或更改已保存的使用者
設定來取得通過。

狀態：已完成固定 PCM 與即時 TTS 驗證。詳細結果、限制及全套驗證
見 [report.md](report.md)。
