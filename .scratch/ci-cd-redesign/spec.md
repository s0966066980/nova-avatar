# CI/CD 逐步驗證設計草案

Status: superseded-by-current-version-local-baseline

使用者已要求依現版重設主要基準。以下逐階段草案保留為歷史設計；現行定義以
[測試指南](../../docs/current-version-testing.md) 與 `tests/current-version-baseline.json` 為準。

## 目標

讓管理者理解每項檢查保護哪些行為、沒有證明哪些事情，以及如何重現結果。
先把本機步驟與紀錄走清楚，再將共同確認的流程搬入 CI，最後接上場域交付。

這份文件是待確認的分階段草案；不是新的 workflow，也不是本次已執行的驗收報告。

## 建議順序

| 階段 | 要回答的問題 | 檢查內容 | 產出與限制 |
| --- | --- | --- | --- |
| 0：來源與環境 | 這次究竟驗證哪份程式、在哪裡跑？ | commit、工作目錄差異、Python/Node/uv/npm 版本、依賴與 CUDA／GPU 環境 | 可追查的執行清單；不以補填的 commit 冒充執行當下證據 |
| 1：依賴準備 | 能否準備 CI 所需的獨立環境？ | `uv lock --check`、隔離 Python 3.11 CUDA 環境、Node 22 與 `npm ci` | 安裝日誌與版本；不覆蓋場域正在使用的 GPU `.venv` |
| 2：靜態檢查 | 已選定的程式規則是否被違反？ | Ruff、Pyright、ESLint | 每項退出碼與日誌；不代表功能正確或所有程式都完成型別檢查 |
| 3：來源與離線整合 | 品牌、授權與離線整合契約是否正常？ | `scripts/check-integration.py`、Python `governance` 群組 | 分開記錄命令結果；不是商業授權保證，也不驗證真實模型服務 |
| 4：後端功能 | 伺服器各責任的已知行為是否退步？ | 其餘 6 個 Python 功能群組，逐組解說與執行 | 群組報告、完整案例清單與 skip 理由；mock 通過不等於外部服務可用 |
| 5：前端功能 | 控制台、舞台與互動規則是否退步？ | 依功能盤點執行現有 Node 測試檔 | 分辨純函式、原始碼契約、jsdom、Chrome；不把模擬後端當真實系統 |
| 6：正式建置 | 前端能否產生可供後端提供的檔案？ | `npm run build` | 建置日誌；尚未包含發佈保存與場域版本切換 |
| 7：場域實機驗收 | 選定組合在真實主機能否完成訪客對話？ | 待確認的模型、語音、GPU、WebRTC 與視聽驗收 | 尚未定義或執行，須和離線 CI 分開記錄 |
| 8：交付與回退 | 能否核准更新並回復至先前可用版本？ | 版本產物、管理者核准、更新後檢查、回退演練 | 待前面階段確認後再設計，不以啟動腳本取代這些責任 |

階段 2–6 在正式 CI 是否並行、是否拆成多個 job，尚待決定。
逐階段教學順序不必等於 GitHub 執行時的排程。

## 已確認的 CUDA 範圍

使用者已明確指定本版只做有 CUDA 的環境，先前 CPU 回歸路線不納入本版。
Python 驗證環境必須安裝 CUDA PyTorch、有可用 NVIDIA GPU，並通過實際 GPU
運算探針；沒有 CUDA 時應失敗，不以 CPU fallback 或 skip 當成通過。

本版採現有 `uv.lock` 與 `pytorch-cu124` 來源，以 frozen 安裝準備獨立環境。
先前 CPU 安裝只是歷史證據；新執行結果以 CUDA 補驗紀錄為準。
現有 workflow 尚為 CPU 安裝與一般 runner，須在整體設計確認後改為 GPU runner。
實際 GPU 模型與場域驗收仍依後續階段確認，不因使用 CUDA 套件而自動算通過。

## 每階段都要留下的內容

1. 目的、保護的使用者行為與未涵蓋範圍。
2. 前置條件、工作目錄、精確命令與測試選取條件。
3. 開始／結束時間、來源版本、工作目錄差異與工具版本。
4. 命令退出碼、pass/fail/skip 數量、原始日誌和結構化報告（若有）。
5. 跳過的案例、理由、影響與後續處理；不能把跳過計入通過。
6. 使用者是否已理解並確認這一階段；執行成功與理解確認分別記錄。

詳見 [紀錄範本](records/TEMPLATE.md)。

## 現有檢查需要講清楚的界線

- Pyright 目前只檢查 `src/server`，並關閉若干既有型別債務規則。
- Ruff 只啟用設定中的語法、部分安全與 async 規則，且排除部分繼承引擎目錄。
- `npm audit --omit=dev` 目前為 advisory；`continue-on-error: true`，不是阻擋門檻。
- 測試案例數量不是程式碼覆蓋率百分比；目前 workflow 未產生行／分支覆蓋率報告。
- 已有 `live`、`slow` 標記；`slow` 是額外屬性，不是第八個 Python 功能群組。
- 未決定新的 skip 白名單；不能直接把「3 個 skipped」固定當成以後都可接受。

## 設計確認後才處理的項目

- 新 workflow 的 job 分工與失敗門檻。
- 每次執行要上傳的報告、保留期限與可追溯版本資料。
- 實機驗收的必測情境、依賴與時機。
- 應用、模型／設定與場域資料的交付邊界及回退方式。
