# 控制台對話版面與操作穩定性

Status: implementation-complete

產品修改與自動化驗證已完成；實際瀏覽器版面驗收因無可用瀏覽器而未執行。

日期：2026-10-29。使用者指定 grill-with-docs，要求修改控制台 UI/UX，
回報「整個版面會因為對話導致版面衝突」。本文件記錄查核事實與設計訪談；
使用者已於 2026-10-29 回覆「是，依此排版開始實作」，確認下方 Q4 的完整
配置與模式狀態保留方案，並授權開始修改產品程式。

## 既有領域與決策

- 使用 [CONTEXT.md](../../CONTEXT.md) 的「控制台」「控制台對話」與
  「數位人舞台」術語。控制台內的數位人影音屬於控制台自己的對話，
  不等於訪客使用的獨立數位人舞台。
- [ADR-0020](../../docs/adr/0020-independent-console-and-stage-conversations.md)
  要求兩場對話獨立；版面調整沿用此邊界。
- [ADR-0010](../../docs/adr/0010-console-rest-state-follows-turn-commit.md)
  規定控制台靜態紀錄依已播回覆提交，版面容量不足不能改變這項語意。
- 目前沿用既有詞彙，沒有新領域術語需要寫入詞彙表；尚無符合長期架構
  取捨條件的新 ADR。

## 設計樹：第一輪與需求補充

- Q3／視覺範圍：沿用配色與品牌風格，集中調整版面、資訊層級與互動；
  另可選整體視覺重設。

## 第二輪：已接受的具體排版

- 把「對話記憶與語系」完整移到系統設定中心的獨立分類。場次選擇、
  各角色記憶、Context 用量、保留上限、語系、雙語聲音與清空操作仍可使用，
  詳細資料不占控制台工作區高度。
- 控制台工具列保留「對話模式／朗讀模式／語音驗證」，另設「對話設定」
  快速入口；進入設定後可返回原本的控制台模式。
- 控制台僅以緊湊狀態列顯示目前角色與回覆語系；狀態列高度不隨記憶
  訊息或 Context 統計增長。
- 三種模式共用同一塊主要空間，各次只顯示所選模式。對話模式顯示訊息
  與輸入區；朗讀模式顯示朗讀編輯與播放；語音驗證顯示測試表單、結果與紀錄，
  不再同時堆疊聊天列表及對話輸入區。
- 模式切換保留尚未送出的文字與已存在的紀錄；切換顯示區不自行送出、
  清空或中止輪次，語音驗證進行中的狀態與結果仍須能回看。
- 桌面延續對話工作區與數位人預覽雙欄；右側影音與連線／錄影控制的位置
  不因記憶資訊更新而改變。沿用現有品牌風格，窄畫面則以可用空間重排。
- 工作區配置須處理可縮小高度與寬度：訊息／驗證結果各在所屬區域捲動，
  模式切換與當前模式的主要操作可達；長內容不能撐寬外層。附件與錯誤顯示
  不能讓送出及麥克風操作被根容器裁掉。

排版草圖：`preview/console-layout.html`。可切換三種模式、進入對話設定並
返回原本模式；它是本機示意，不連接後端，也不能執行真實送出、錄音或設定套用。

Q4／共同理解確認：是否採用以上配置，將記憶與語系移至設定中心，並讓
