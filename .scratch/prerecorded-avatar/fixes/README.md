# 預錄數位人操作修正驗證 — 2026-10-13

使用者回報呈現方式切換卡住、兩種模式畫質混用、預錄啟動過慢、
兩種影片下載失敗，以及控制台與舞台連線互相影響。修正已在 Jetson
AGX Orin 與 Chromium 154 上完成實機操作與回歸；此目錄是偵錯與
驗證資料，不是正式服務的啟動入口。

## 原因與修正

| 問題 | 已確認的原因 | 修正 |
| --- | --- | --- |
| 模式切換卡住 | 選擇即提交重載；GPU 重載佔用 HTTP 執行緒；兩端會話尚在使用角色 | 選擇與套用分開；預設通知兩端結束當前對話後重連；重載在背景工作，獨占鎖直到工作完成才釋放；相同模式略過重載 |
| 畫質不符合模式 | 預錄合成沿用 MuseTalk 的最大高度 | 預錄直接使用素材尺寸；即時畫質設定僅在即時模式顯示並保留 |
| 預錄啟動慢 | 無麥克風會話仍準備語音輸入；外部 STUN 等待；待機與 RTCP 校準串行 | 純觀看略過 VAD/STT；有收音時平行準備且準備前關閉收音；區網預設主機 ICE；先顯示待機再校準 |
| 下載被取消 | Chromium 在自簽 HTTPS 下取消直接影片網址下載 | 控制台錄影、舞台錄影與素材皆用同源 fetch 取得 Blob 再下載，提供 HTTP／空檔錯誤提示 |
| 重連與名額衝突 | 失敗、取消、重新整理留下舊會話；停止後的非同步回呼可能操作新會話 | 每種頁面保留自己的 client ID；明確釋放與替換同頁舊會話；失敗／取消清理；前端忽略過期回呼並等待健康就緒 |

額外回歸：接收端 RTCP 晚到時，原先的錯誤旗標會永久阻止說話與
錄影；改為持續等待與自動恢復。舞台重連保留已暫停的收音選擇。
時鐘影像軌保持解碼，但隱藏於使用者畫面，避免閃現低解析度影像。

## 實機操作

真實控制台與舞台同時連線，透過設定面板往返切換兩輪；兩端
總共十次協商皆為 HTTP 200，沒有頁面錯誤。

| 測量 | 結果 |
| --- | --- |
| MuseTalk 套用並恢復雙畫面 | 35.8 秒、31.1 秒 |
| 預錄套用並恢復雙畫面 | 7.5 秒、6.4 秒 |
| 預錄已準備時的 offer 請求 | 36.9–97.8 ms |
| 單端首次 offer，修正前 → 後 | 21.26 秒 → 2.25 秒 |
| 單端待機顯示，修正前 → 後 | 23.47 秒 → 4.41 秒 |
| 重新整理與快速停止／開始 | 九次協商全部 HTTP 200；關閉頁面後測試會話釋放 |

模式往返包含資源釋放與重載，不能當作一般連線耗時。首次連線與
已準備的 offer 是不同實驗，沒有合併計算。實測依當時負載而異。

資料：[模式與下載](browser-verification.json)、
[重新連線](reconnect-verification.json)、
[啟動前](startup-before.json)、[啟動後](startup-after.json)。
`startup-baseline.json` 是早期腳本命名，內容與 `startup-after.json`
相同。HTTP 不被重載阻塞另以非同步 heartbeat 回歸測試驗證；
`health-during-switch.json` 的實測採樣沒有碰到切換，不能作為此項證據。

## 下載與播放

控制台錄影 1,291,582 bytes、舞台錄影 1,206,514 bytes、素材
3,767,127 bytes，實際下載皆成功。三支影片全部解碼為 H.264
1080×1920；兩支錄影有音軌，素材無音軌。
見 [影片檢查](download-validation.json)。

下載問題使用相同網址比較：直接下載被取消，fetch／Blob 成功；
僅加入 Chromium 憑證略過參數後直接下載也成功，確認自簽 HTTPS
是該環境的觸發條件。正式下載修正沒有要求關閉瀏覽器憑證檢查。
見 [下載修正前](download-baseline.json)、
[憑證對照實驗](download-tls-bypass.json)。

最新 25 秒雙端朗讀／中斷／錄影測試，素材 1080×1920，
控制台／舞台畫布約 25.03／24.10 fps，最大更新間隔
66.7／83.3 ms，素材解碼丟幀皆為零；兩端均收到有效音訊、切換
說話／待機、成功匯出 MP4，沒有頁面錯誤。
見 [最新播放與錄影音訊檢查](playback-final.json)。

使用者已確認實際由另一台電腦的瀏覽器／喇叭播放聲音。本機 Chromium
音訊輸出遇到設備限制，最終自動播放測試使用
`--disable-audio-output` 測試輸出，驗證接收、解碼與錄影音訊，
沒有變更 Jetson 音效設定。這項短測不代表已測到遠端實體喇叭或
真實麥克風，也沒有完整逐字比對參考 PCM。控制台與舞台各有獨立
對話，兩端同時回答時會各自播放音訊。

## 回歸與交付狀態

| 指令 | 結果 |
| --- | --- |
| `uv run python scripts/check-integration.py` | 整合、品牌、授權全部通過 |
| `uv run pytest` | 570 passed、4 skipped、1 既有失敗 |
| `cd web` 後 `npm test` | 103 passed |
| `cd web` 後 `npm run build` | 通過；大 chunk 警告 |
| `git diff --check` | 通過 |

Python 唯一失敗仍為原有全尺寸 CPU 去背效能測試
`test_chroma_composite_fits_the_render_frame_budget_on_a_portrait_avatar`：
本輪中位數 35.55 ms，要求小於 30 ms。未放寬門檻。
預錄使用瀏覽器合成路徑；此失敗仍保留為即時模式的效能限制。

新增回歸涵蓋失敗／取消的協商清理、兩種頁面容量、純觀看不準備
語音輸入、背景重載期間 HTTP heartbeat、預錄原尺寸、
停止後晚到的麥克風回呼、晚到 RTCP 時鐘與舞台暫停收音的重連。
完整輸出保留於本機 `integration.log`、`pytest.log`、
`web-tests.log`、`build.log`，日誌不納入版控。

使用者既有設定與測試前備份比較沒有差異，保留目前角色的預錄
模式、原尺寸與原背景，以及 LLM／TTS／RAGFlow 設定。
正式服務仍為 8010／3000；臨時 8011 RTP 實驗服務已停止，
臨時 RTP monkeypatch 已刪除。偵錯腳本僅留於本目錄，正常服務
沒有使用它們。
