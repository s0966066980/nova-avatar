Status: 使用者已接受整體設計；功能已實作，雙舞台瀏覽器驗收通過。

更新日期：2026-10-27。

## 已確認需求

- 數字人舞台新增英文介面與英文語音對話，保留既有中文。
- 舞台初次開啟時直接選擇呈現語言，取代目前「點擊進入」的操作。
- 舞台內可以即時切換語系。
- 控制台介面維持中文，新增或整合數字人語音與回覆語系的切換控制。
- Q3 已確認：舞台「繁體中文／English」同步舞台介面、語音辨識、LLM 回覆（含字幕與看板）及數字人語音；舞台內保留語系切換入口。
- Q4 已確認：不同舞台各自持有對話語系、互不影響，控制台另外管理新對話預設。
- Q5 已確認：切換時立即停止舊回答，保留已說出的內容及既有對話，下一次發話使用新語言；舊字幕與看板保留原文、不自動翻譯。
- Q6 已確認：中文、英文各保存一個預設聲音，切換回覆語系時套用對應聲音，管理者可分別更換。
- Q8 已確認：控制台可選自己的對話或某個已連線舞台檢視記憶並控制語系／聲音，另設新對話預設，不影響其他既有對話。
- Q10 已確認：語音輸入允許中文、英文或混說，介面與回覆固定依所選語系，不依辨識結果自動跳換語系。
- Q12 已確認：切換期間暫停收音並丟棄尚未提交的半段發話；準備好後恢復。失敗保留原語系並顯示錯誤，已停止的回答不自動重播。
- Q13 已確認：每次新開舞台顯示雙語入口；同頁短斷重連沿用語系，若新 session 導致歷史清空則明確告知。語言按鈕本身是進入與請求麥克風權限的操作。
- Q11 已確認原先依本機實測選型的方向，另新增須提供可本機部署、可商用的非中國來源語音辨識候選。
- Q17 已確認此為正式採用的必要條件：主要開發機構與基礎權重非中國大陸；訓練資料與教師來源另外列明已知／未知。FunASR、Paraformer、SenseVoice 僅保留作比較基準，不列為正式選型。

## 訪談時查證現況（實作前）

- `web/stage.html` 入口目前使用「數字人舞台」、「點擊進入，瀏覽器會詢問麥克風權限。」與「進入」按鈕；舞台另有中文麥克風狀態、字幕與看板操作文案。
- `web/src/composables/useI18n.js` 已有 `zh-TW` 與 `en-US` 字典入口；這不代表獨立舞台已套用英文化。
- `web/src/components/SettingsPanel.vue` 已有 LLM 輸出語系選項，語音辨識與語音合成也已有設定。
- [ADR 0015](../../docs/adr/0015-console-owned-assistant-profile.md) 將輸出語系列為控制台集中保存的助手設定；若改成各場對話可獨立切換，需要明確說明持久預設與對話中的選擇之關係。
- [ADR 0006](../../docs/adr/0006-support-only-keyless-speech-engines.md) 限定支援不需外部憑證的語音引擎；語音方案仍需遵守此約束。
- STT 引擎目前共享可變的 language 欄位，現有語音設定套用 API 也要求所有 session 先中斷；舞台即時切換需新增各場對話的語系契約，不能直接呼叫部署設定 API。
- Edge 語音設定白名單目前僅列臺灣中文聲音；需加入英文聲音。FunASR 目前只開放 `paraformer-zh` 模型選項，並將回傳的 language 固定標成 `zh`；這不代表解碼器完全不能辨識英文。GPT-SoVITS 與 XTTS 的既有 adapter 另有固定中文設定；支援英語的引擎範圍需確認。
- 現有助手 profile（包括 output locale）變更會觸發所有 LLM 實例清空歷史與看板，與本次「各舞台獨立、語系切換保留記憶」要求不同。此處是本次要改變的架構邊界，不是現況已支援的行為。
- `config/runtime_overrides.yaml` 當時儲存的辨識引擎是 FunASR、語音合成為 Edge TTS；不能以基礎 YAML 的 Whisper 預設當成目前生效設定。

## 第一輪訪談

### Q3：語言選擇是否同步整個舞台體驗

已確認：舞台入口「繁體中文／English」一次同步舞台介面、語音辨識、LLM 回覆（含字幕與看板）與數字人語音；控制台介面維持中文。舞台內提供相同切換入口。

### Q4：各場對話是否獨立

已確認：不同舞台 session 可同時使用不同語言，互不影響；控制台另外管理新對話預設。控制台是否可以指定目前某場對話及預設如何保存，留待下一輪追問。

### Q5：輪次中切換的行為

已確認：切換時立即停止舊回答，依現有契約保留已播回覆與已顯示看板，下一次發話使用新語言；既有歷史、字幕與看板保留原文，不自動翻譯。

### Q6：聲音與語言的對應

已確認：中文、英文各有可由控制台設定的預設聲音，切換回覆語系時套用對應聲音；管理者可以分別更換各語系聲音。

## 互動與狀態契約

- 語言按鈕直接進入舞台並觸發所需權限，不再要求先按一個額外的「進入」按鈕。入口同時提供「繁體中文／English」，手機與桌面皆可操作。
- 舞台靜態文案、動態狀態、看板操作、錯誤與重試提示及可及性標籤均跟隨目前語系；LLM 口語、字幕與新看板內容亦使用所選語系。
- 控制台對已連線舞台修改語系時，該舞台同步呈現實際生效語系；目前場次操作與新對話預設分開，新對話預設儲存後不回寫其他既有場次。
- 切換成功以前呈現準備中並暫停收音；成功確認後同步更新介面及後端語系。失敗回到原語系並顯示可重試錯誤，不呈現前後端已切換的假象。
- 語系切換不改變助手身分、不清空對話、不翻譯舊字幕／看板；原有閒置清空與新 session 建立仍依各自邊界處理。
- 預錄呈現與即時嘴型使用相同語系、語音與輪次契約。

## Q11 技術釐清

FunASR 是工具框架，英語能力取決於所選模型。[官方 `paraformer-en` 模型](https://huggingface.co/funasr/paraformer-en)支援英語；[官方 `SenseVoiceSmall`](https://huggingface.co/FunAudioLLM/SenseVoiceSmall)支援包含中英文的多語辨識；目前[官方 `paraformer-zh` 模型卡](https://huggingface.co/funasr/paraformer-zh)也列出中英混合辨識能力。先前將本機整合概括為「只處理中文」過於絕對，不能由固定回傳 `language="zh"` 推導模型完全不能辨識英文。

本機既有權重的完整英文及中英混說品質仍未驗證，與官方模型宣告分開記錄。僅切換 language 設定不會自動替換 checkpoint，也不會補足多語模型的標籤清理與部署驗證；是否保留 FunASR、選哪個模型仍待使用者決定。

本機 metadata 識別為 `iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-pytorch`，目錄未記錄可對應目前官方模型卡的確切上游 revision。已安裝 FunASR 1.4.15，其隨附文件將 Paraformer-zh 列為 `zh/en`，並已提供含英文的 SenseVoiceSmall 實作；這是框架與模型家族能力的證據，不取代本機辨識品質測試。

## 語音辨識選型要求

- 正式候選需可本機部署、權重授權允許商用，且主要開發機構與基礎權重非中國大陸。
- 需支援中文與英文，另外測試中英混說；具備語言清單不等於已達成實際辨識品質。
- 資料或教師來源有揭露時明列，未揭露時標示未知；不宣稱整條訓練資料供應鏈沒有中國來源。
- 以現有 Jetson 與數位人共同運作的條件驗證品質、辨識延遲與資源；公開排行榜、x86 GPU 範例與標示可下載都不能取代本機驗收。
- 訪談階段先提供研究與候選建議；使用者接受 Q18 後已下載官方 Whisper small／turbo，完成本機轉換及比較，現用設定為 Whisper small／自動辨識。

## 實作與驗證結果

- 舞台雙語入口、即時切換及控制台的場次／新對話預設已完成。中文與英文各保存聲音，控制台文案維持中文；各場 LLM 設定、對話及收音偵測器獨立。
- Edge TTS 沿用既有線上服務；Whisper 辨識在本機 CUDA FP16 執行，兩個候選均直接由官方 OpenAI 權重轉換，保留 revision、授權及雜湊。[來源紀錄](asr-benchmark/model-manifest.json)
- 八題合成語音比較：small 暖測中位 0.575 秒、程序 RSS 1.591 GiB；turbo 1.327 秒、2.984 GiB。採 small 以兼顧延遲與資源；turbo 已可於設定 API 選擇。混說仍有誤辨，並非真人口音或噪音品質驗收。[完整品質邊界與逐字](asr-benchmark/product-corpus-report.md)
- 以兩個實際 WebRTC 舞台完成英文語音、中文輸入但英文回答、跨語系追問 NOVA42、控制台場次保留上限、說話途中切換及同頁重新連線；收到的音訊具有非零能量，瀏覽器沒有 JavaScript 錯誤。[瀏覽器證據](verification/browser-results.json)
- 另已實際切換英文聲音為 Aria，產生三個英文看板項目與英文口語，確認新看板不沿用中文提示範例。[英文看板證據](verification/english-board-results.json)
- 已實際從控制台清空選定英文舞台的記憶與看板。[清空證據](verification/clear-session-results.json) 切換語系時，重採樣、端點偵測與手動收音收尾均檢查輪次世代，丟棄仍在背景處理的舊音訊；回歸測試涵蓋新語系已恢復收音及尚未恢復兩種時序。
- 多舞台驗收發現並修正原有 Silero 共用可變模型造成的 native 崩潰；兩個獨立模型各 2,000 次並行 reset／推論完成，另加入多收音模型隔離回歸測試。[修正前](vad-concurrency-before.log)、[修正後](vad-concurrency-after.log)
- 本機目前為預錄數位人呈現，已驗證其活動語音鏈路；本次沒有重新測量即時嘴型引擎的多舞台效能。真人口音、現場噪音與完整商用部署授權仍須依個別模型／聲音／服務條款評估。

## 驗收案例

- 新開舞台直接選英文即可進入；麥克風權限拒絕及重試文案依語系呈現，控制台介面仍維持中文。
- 中文與英文舞台同時使用時，辨識與回覆語系互不污染；控制台選定 A 場次操作不改變 B 場次。
- 中文回答播放中切到英文，舊輪次未播內容停止且不再次送出；下一輪可以用英文追問保留下來的前文。
- 英文模式輸入中文、英文或混說時，辨識盡可能保留原意，回答與新增看板使用英文；中文模式反之。
- 切換中發話片段不誤送新語系；切換失敗保留原設定並可重試，不重播已停止的舊回答。
- 新開頁面回到語言入口；同頁斷線重連沿用所選語系，若新對話導致記憶清空則提示。
- 正式採用模型逐一附官方權重授權與來源證據，並在本機數位人共同負載下驗證中英文品質、辨識延遲及資源使用；不以授權符合或模型成功載入代替品質驗收。

技術能力參考：[faster-whisper 語言偵測介面](https://github.com/SYSTRAN/faster-whisper#usage)、[Edge TTS 聲音選擇](https://github.com/rany2/edge-tts#changing-the-voice)。實際辨識品質與延遲仍須以此專案部署驗收，不能由上游功能表推定。
