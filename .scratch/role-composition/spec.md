# 當次角色組合：一主多專、任意角色直接交接

Status: resolved

使用者 2026-10-30 確認 Q1–Q14（Q3 依原型 https://claude.ai/artifact/4mU4t5YbEDPTQv9FUSmhMy 新版）。決策紀錄：[ADR 0023](../../docs/adr/0023-role-composition-with-any-to-any-handoff.md)。術語：`CONTEXT.md` 的主數位人、專門數位人、當次角色組合、角色交接、反向角色交接、交接規則、交接說明、角色轉場、場域預設地點。現況與寫死兩角色的位置：`/tmp/claude-1000/-home-oliver-nova-avatar/f284899e-3e7d-40e8-bf07-77d0ecc09394/scratchpad/notes/role-pair-map.md`。原型檔：[`prototype/role-composition.html`](prototype/role-composition.html)。

## 決定

- **頁面**（Q1）：移除系統設定中心的「返回控制台」。「訪客互動與語音辨識」併入「數位人、AI 與知識設定」，成為第三個分頁：數位人設定檔｜角色組合與交接｜訪客互動與語音辨識；設定內容與行為不變（全域設定）。
- **組合**（Q3、Q4）：單一組合；一位主數位人＋最多五位啟用中的專門數位人；未啟用者保留設定。版面依原型：左側成員名單、中間所選成員的設定、右側交接路線與角色轉場。
- **任意角色直接交接**（Q2、Q11）：每一輪路由在所有啟用成員（含主數位人）中選回答者；任一位可直接交給任一位。主數位人只負責開場與兜底，也是「返回主數位人」的目的地。
- **成員欄位一致**（Q12）：每位成員（含主數位人）有專長介紹、何時交給它（交接規則）、交接說明 中／英；不再有「返回說明」與「何時交回主數位人」。交接說明由目前角色說出，每位目的角色一句。
- **追問留在目前角色**（Q13）：延續上一題的追問不交接；明確換主題才交接；混合主題先確認。
- **各自保存**（Q7、Q8）：交接設定存在組合成員上（不在數位人設定檔）；每位成員有自己的儲存與修訂版本，改一位不影響其他位；只有主數位人與啟用名單等整體變動才檢查整份組合的版本。
- **轉場**（Q9、Q14）：一份預設轉場＋任意來源→目的的個別覆寫。
- **天氣工具**（Q10）：場域預設地點屬於持有天氣工具的成員；天氣工具同時只限一位；關鍵字初篩從任何角色都導向該成員。
- **共用服務**（Q6）：所有啟用成員共用同一套語音合成引擎與回答模型服務（含 BreezyVoice 的伺服器與模型）；不相容者無法啟用並說明原因。
- **範圍**（Q5）：只做架構與介面，不建立新角色內容；現有天氣助手與交接規則自動轉換為組合的第一位專門數位人。
- **交接試算**（原型新版）：在組合頁提供「目前角色＋測試問題 → 由誰回答、原因」的試算，實際呼叫路由（不播報、不寫入對話）。
