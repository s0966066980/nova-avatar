# 分送目前輸入端的影音與問答

Type: task
Status: resolved

## 重現

`uv run pytest tests/test_webrtc_lifecycle.py -k active_questions -q` 在修正前兩種模式皆失敗：另一端的提問與已播回答事件列表為空。

## 原因與修正

兩端原本各自使用一個人物播放器及事件接收端。新增共用展示層，以輸入來源決定兩端顯示的內容，分送同一份實際播放音畫、字幕與看板；生成預覽仍只發給原輸入端。每條連線保留自己的事件序號，補齊目前場景時清除舊展示，對話記憶仍由原工作階段保存。

媒體在分送出口再次檢查來源、取消代數與人物代數；每個傳送端使用獨立影格並維持連續時間戳。輸入端保留音訊背壓，觀看端使用有限緩衝。看板收據轉交回答來源並沿用去重。修正明確選擇控制台測試後，新開舞台會自動取回輸入權的問題。
