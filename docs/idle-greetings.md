# 閒置招呼

1. 在控制台的「系統設定」側欄，直接選擇 **閒置招呼**。本頁集中主數位人的招呼開關、間隔、內容模式、Prompt、字數範圍、預覽、試播與執行狀態。
2. 選擇內容來源：
   - **AI 自動生成（Prompt）**：在同頁出現的「AI 招呼 Prompt」填寫指令，設定最少／最多字數，預設 20～60 字。AI 沿用主數位人的身分、語系與限制，不讀取訪客對話、知識庫或交接工具。
   - **隨機預寫文案**：新增一篇以上招呼詞或自我介紹。有多篇不同內容時，不連續播同一篇。
3. 在同頁設定 **啟用閒置招呼** 與 **閒置多久開始準備招呼**，按 **儲存並套用招呼設定**。功能預設關閉、間隔預設 60 秒；啟用時必須填妥所選模式的必要內容。儲存與套用都在本頁完成，無須前往舞台或角色設定頁。
4. 可先預覽草稿及字數，或在已連線的控制台試播，不必先儲存。試播使用目前連線的人物與草稿聲線；不同語音引擎類型須先載入。完成後在同頁按「返回訪客模式」。
5. 啟動訪客舞台並允許麥克風、有聲播放。控制台測試、純觀看、音量為零、靜音或手動暫停互動時，不會自動招呼。使用自動收音模式，才能在招呼準備時接受訪客語音。

訪客模式由舞台接收現場提問，並自動招呼；控制台測試模式讓管理者試播與發問，暫停舞台輸入，避免測試與現場互相干擾。**編輯、儲存與預覽 Prompt 都不需要切換模式**，只有試播才暫時切換。正常現場使用維持訪客模式即可。

要驗證舞台效果，讓控制台與 `/stage.html` 都保持連線。控制台測試時，舞台同步呈現測試中的聲音、嘴型、提問、已播字幕與看板；訪客模式則由舞台收音，控制台同步顯示舞台目前的問答。切換模式或晚開頁面時，畫面會補齊目前一輪的已播內容；已明確選擇控制台測試後，開啟舞台不會自動切回訪客模式。

設定依用途集中：

| 設定頁 | 管理內容 |
| --- | --- |
| 閒置招呼 | 啟用、間隔、文案／Prompt、字數、預覽、試播及招呼狀態 |
| 訪客互動 | 訪客對話重置時間、免持收音、發話門檻與停頓判定 |
| 舞台與看板排版 | 場景背景、字幕顯示、看板外觀／位置及舞台按鈕位置 |
| 語音辨識與合成 | STT／TTS 引擎與相關語音設定 |

排版頁儲存不會提交招呼或訪客互動草稿；招呼頁只套用主數位人的招呼內容，不會讓其他已儲存、尚未套用的角色身分或模型修改一起生效。各頁套用後留在原頁。招呼內容若已儲存但後續套用失敗，本頁會保留草稿並顯示錯誤，可在同頁重試。

間隔代表**開始準備**的時間。先完成上一位訪客的清場並返回主數位人，才會準備招呼；例如清場 120 秒、招呼 60 秒，會等清場及返回後準備一次。AI 最多生成兩次、共用 15 秒預算，語音合成時間另計。失敗略過本次，下一個間隔再試；閒置招呼頁每五秒更新招呼狀態與不含敏感資料的失敗原因，也可手動更新。

準備期間訪客發話會取消舊招呼；正式播放後使用既有收音暫停與點選插話。招呼只保留最近一次實際播出的文字供追問，反覆招呼不新增假訪客提問、不堆疊對話歷史。字數以前後端一致的 Unicode 字素計算，包含標點，忽略 Unicode 空白；預寫文案超出範圍仍可播放。只有表情符號而沒有可朗讀文字的文案會略過並提示。

更新招呼內容、模式、字數或間隔會取消未播放的準備，已播放的招呼可講完；停用、斷線、切換角色或進入控制台模式會立即取消。重新連線、恢復互動或回到訪客模式後，重新等待完整間隔，不補播錯過的招呼。

內容保存於 `config/avatar_profiles.yaml` 各設定檔的 `greeting`；舞台開關與秒數保存於執行時舞台設定的 `idle_greeting_enabled`、`idle_greeting_seconds`。舊設定自動取得關閉／空內容預設。

設計與驗收條件見[功能規格](../.scratch/idle-greeting/spec.md)與 [ADR-0018](adr/0018-separate-idle-greetings-from-visitor-turns.md)。
