# 對話附件與舞台文字輸入

控制台聊天可附加 PDF、JPG／JPEG、PNG、WebP；先選檔、檢查預覽及輸入問題，再按送出。可拖放檔案或貼上圖片；只有檔案時預設摘要文件或說明圖片。

在「系統設定中心 → 舞台與看板排版」開啟「舞台文字與附件輸入」，按「套用舞台設定」。預設關閉，開關及外觀套用所有舞台；檔案、對話與語系各場獨立。控制台介面維持中文。控制台與舞台可各自送出問題，對話、影音及收音互相獨立，無須切換輸入模式。

同一區可調整輸入框位置、寬度、高度、字級、背景不透明度、中英文提示文字，也可在預覽拖曳輸入框；滑桿提供不用拖曳的替代操作。輸入框高度可設定 120–480px，以 405×720 舞台為基準等比縮放。預覽與實際舞台共用相同輸入元件與換算；附件、處理狀態或來源文字增加時，內容在框內捲動，外框不會自動增高。字幕區與輸入框接近時，預覽及舞台都會保留回覆空間。手機鍵盤開啟時暫時調整可視位置及高度，收起後恢復保存的位置。

## 問題、追問與取消

- 送出前可移除檔案、編輯問題；PDF 可在附件清單指定頁碼，例如 `1-3,5`，空白為整份。
- 「本輪參考附件」勾選的是這一題及語音追問使用的檔案；取消全部選取即回到一般對話。附件不自動加入 RAGFlow 永久知識庫，也不因歷史訊息達保留上限就刪除。
- 所有新附件通過檢查後才接受新問題、插話停止舊回答；驗證失敗保留草稿。接受前保留本機檔案，接受後可使用已上傳檔案重試。
- 上一題仍顯示「傳送中」時，可繼續編輯並按送出、Enter 或點快捷指令插話；新問題立即取代仍在傳送的請求。晚到的舊回應不會覆蓋新問題；只編輯而未送出的下一題草稿會保留。
- 支援上傳、讀取、分析、回答狀態及取消。取消不再交付舊任務尚未輸出的內容；已播內容依既有對話提交規則保留。
- 個別刪除附件會刪原檔及停止後續引用，先前回覆與歷史文字仍存在；要遺忘整場內容請完整清空。
- 桌面 Enter 送出、Shift+Enter 換行；中文輸入法選字確認不送出。手機使用送出按鈕。編輯及選檔暫停收音，結束後恢復原先狀態。
- 進入舞台會請求麥克風權限，允許後依免持模式自動收音；開啟文字與附件不會延後收音。拒絕權限或沒有麥克風時，仍可用文字與附件，需要時再按麥克風重試。

## 角色交接與語系

附件屬於本場舞台對話或控制台對話；主數位人與專門數位人的記憶仍分開，
交接沿用本輪選取的附件。目的角色不支援視覺時，在交接前提示並留在原角色，
不會自動切換模型。每場語系跨角色保持一致，各角色的中文與英文聲音可在
「數位人設定檔 → 聲音與工具」保存。

## 容量與生命週期

| 限制 | 值 |
| --- | --- |
| 單檔原始大小 | 20 MB（20,000,000 bytes） |
| 單輪新舊參考附件 | 合計最多四個 |
| 整場保留附件 | 最多 20 個，原始檔合計 200 MB |
| 單輪 PDF 頁面／圖片 | 合計最多 40 頁／張，可選頁碼縮小範圍 |
| 原始圖片 | 最多 2,400 萬像素 |
| PDF 上傳可檢查頁數 | 最多 1,000 頁；每輪仍以選頁 40 頁為限 |
| 本機頁面視覺輸入 | 長邊最多 1,024 像素，逐頁處理 |
| OCR 輸入 | 長邊最多 1,536 像素，本機程序、單次最多 20 秒 |

加密 PDF 須先解密。超出容量會提示縮小檔案、選頁或移除舊附件。原始檔配額不等於模型 Context 或執行期記憶體；最終請求仍須符合模型實際 Context。

控制台與舞台的短閒置清除預設為 15 秒，只清提問字幕、回答字幕及看板；60 秒閒置才清本場各角色的對話記憶、附件及草稿並返回主數位人，保留語系、聲音及外觀。兩端各自從最後操作或回答完成起算，上傳、分析及回答期間暫停；一端清空不影響另一端。

同頁短斷線保留未送本機草稿，不自動送出；若重連建立新場次，已送附件須重傳。舞台斷線期間仍套用 60 秒草稿清除。刷新或關頁不復原草稿及附件。關閉舞台功能會清未送草稿；已接受的回答可完成，已送資料沿用完整清空規則。

完整重置後，空場才重新等待 30 秒準備招呼，從最後互動起最早為第 90 秒；
有任何訪客角色記憶、附件或草稿就不招呼。最近一次已播招呼不算訪客紀錄。
管理者可以手動清空選定場對話，保留其角色、語系與收音暫停狀態。

## 本機處理與部署

PDFium／pypdfium2 擷取 PDF 文字並渲染頁面。Tesseract 在本機補充圖片及掃描頁的繁中／英文 OCR；圖片與 PDF 頁面由 llama.cpp / libmtmd、匹配的 `mmproj` 與語言模型分析。`mmproj` 是影像編碼／投影權重，PDF 解析仍由 PDFium 負責。

目前自動載入僅支援已驗證的配對：

- 文字模型：`llama/gemma-4-E2B_q4_0-it.gguf`
- 投影權重：同目錄的 `gemma-4-E2B-it-mmproj.gguf`
- 官方來源：[Google 固定版本](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf/tree/675cff42a74c774d6cb76f76d8eacb49b48c9b93)
- Projector SHA-256：`021059cce659fe7f9170d5599761d7bbaf644b798dab9503aca30dc43e6beb14`

重啟後端或重新套用模型會載入配對權重；未提供相容視覺能力時，附件按鈕顯示原因，純文字仍可使用。模型目錄內的 `mmproj` 不會被列為可單獨選取的語言模型。

Python 依賴由 `uv sync` 安裝。Ubuntu 的 OCR 依賴可安裝：

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-eng tesseract-ocr-chi-tra
```

本次 PC 已測環境為 pypdfium2 5.14.0、Tesseract 5.5.0、官方 `chi_tra`／`eng` 權重。OCR 缺失或失敗時，請求會標示文字辨識限制，視覺仍嘗試理解畫面。來源、適用授權及二進位通知見 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)。OCR 的完整訓練資料來源尚未全面稽核。

解析與 LLM 分析在本機；現有 Edge TTS 是線上服務，朗讀文字可能包含附件摘錄。

## 分析範圍及已知限制

逐頁讀取產生觀察；長文件分批彙整。針對特定印刷欄位的問題，先辨識欄位名稱與語言別名，再用原始文字核對相關頁面，降低不同代碼或數字混淆。頁面文字／OCR 可在預算內原文保留，來源標示包含檔名及選用頁碼。附件與其中的指令一律是參考資料，既有角色、限制 Prompt、回覆規則及場次語系繼續生效。

來源 Jetson 曾驗證代表性數字／圖表及 40 頁處理，也曾出現長文件重述與加總錯誤；這些不是本次 PC 的驗證結果。本次 PC 實測涵蓋中英文代表性圖片、掃描 PDF、文字 PDF、OCR 與數字欄位追問；圖表及 40 頁長文件正確率須另依實際資料驗收。實作保留原文與欄位核對，仍不保證任意文件的所有細節或計算正確。需要精確查核時可選較小頁碼範圍、對照原檔。

文字 tokenizer 無法完整計量影像特徵；模型回報請求用量前，控制台會標示只有文字估算、圖片用量待回報，隱藏尚不能確定的剩餘比例。取得 provider usage 後以實際輸入用量更新；不把圖片 base64 當作文字 token。

## PC 安裝與驗證紀錄

`uv sync` 安裝 PDF 依賴。已有本機 OCR 時優先使用；本機也可使用
`.local/ocr-packages/root/usr` 內的 Tesseract 與配對語言包。
Gemma 與投影權重放入模型目錄後，由管理者選擇並套用；移植不自動替換
既有 Qwen，投影權重不會列成可單獨選取的 LLM。

設定遷移可執行 `uv run python scripts/migrate-pc-conversations.py`，先保留
權限 0600 的原設定備份，再套用 15／60／30 秒與 Whisper small／auto。
此命令不啟用招呼、舞台文字或 RAGFlow 模型統一服務。

本次測試範圍與原始結果見 [PC 移植驗證](../.scratch/jetson-to-pc-port/validation/README.md)。
