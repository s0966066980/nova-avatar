# 對話模型、角色與回覆規則

控制台的「套用模型」只切換對話模型與推理設定。已儲存的助手名稱、
System Prompt、限制 Prompt、輸出語系及三區回覆規則會繼續共用；
尚未儲存的角色與規則草稿也會保留。

「儲存 Prompt 與規則」一次儲存角色與三區規則，不會切換尚未套用的模型。
修改角色會清除舊身份的對話與看板上下文；只改回覆規則則從下一輪生效。
儲存失敗或版本衝突時，保留草稿供重試。

- **System Prompt**：身份、服務範圍、語氣與回答原則。
- **限制 Prompt**：不應承諾、回答或宣稱的內容。
- **看板啟用規則**：讓同一個語言模型決定本輪使用簡答或看板。
- **口語回答規則**：語氣、結論與摘要內容。看板模式使用一句完整總結。
- **看板內容規則**：具體說明、比較依據、項目數與追問方式。

不需在角色 Prompt 裡另寫模式標記、JSON 格式或針對 Qwen、LFM 的格式指令。
系統共用兩種完整格式：簡答只有口語；看板包含口語摘要和獨立的項目資料。
語音、字幕與對話歷史使用解析後的口語文字，看板資料另行顯示。

llama.cpp 上的所有模型共用格式約束；LFM 的思考封裝由後端處理。
其他相容後端使用相同 Prompt 與語音檢查，不會收到不支援的 GBNF 參數。
看板口語若仍按「首先、其次、最後」逐項列舉，系統會改用簡短的看板提示，
保留完整看板內容。這個保護只作用於模型已選定的看板模式；
使用者要求純口述時仍可口述步驟。

格式約束不保證模型的事實、模式選擇或項目數永遠正確。
更換模型後可用問候、隱含多步驟、差異比較、指定三項看板與純口述五種問題驗證。
