講話中切換背景

後端先載入新背景，再以約 0.2 秒淡接；不重建數字人或 WebRTC 連線。現有 musetalk_avatar 作為綠幕試用素材，不重建原檔；其他舊角色不自動套用色鍵。

控制台未連線時顯示合成靜態預覽，連線後顯示 WebRTC 畫面；背景與角色各自持久化。刪除非使用中角色會移至 data/avatars/.deleted/；未選用的背景也能移入 data/backgrounds/.deleted/。兩者都可在控制台復原；封存的數字人也可在確認後永久刪除。

仍待實測／後續

畫質與跨角色轉場

目前依綠色差值即時計算柔邊，並在交界附近壓低綠光；尚未保存逐幀全身 alpha，綠衣、髮絲及邊緣仍須實測。既有影格內嵌文字屬原片像素，色鍵不會移除。

背景可在講話中切換；數字人切換仍須斷開會話。跨角色不斷線轉場與按項目派工尚未實作。

新角色保留 source.* 原片，avator_info.json 記錄 Nova Avatar 來源與相對路徑。既有角色素材與授權註記保持原狀。

01 / Current architecture

修改前的專案架構

控制台與獨立舞台都向 Python 後端建立 WebRTC 連線。每條連線都用伺服器當下的全域模型與素材建立一個 Avatar 執行個體；語音輪次由後端負責。

瀏覽器介面
Vue 控制台對話、設定、影片匯入、數位人選擇；web/src/App.vue、useRuntimeSettings.js
獨立舞台web/stage.html：單一 video 元素、字幕、看板與麥克風
WebRTC 客戶端接收音訊／影像；傳送麥克風與 voice-events
Python 後端
HTTP 設定與匯入 API/api/avatar、/api/avatars/import、/api/stage
WebRTC /offer + ServerState全域 model、avatar；每個會話建立 BaseAvatar 與 VoiceTurnSession
對話輪次編排VAD → STT → 可選 RAGFlow → LLM → TTS；輪次隔離與已播回覆提交
生成與輸出
數位人素材data/avatars/{avatar_id}：影格、嘴型遮罩、座標、latents
MuseTalk 等引擎以音訊特徵生成嘴型，貼回原始影格；主要路徑為 MuseTalk
HumanPlayer將 BGR 影格與音訊送到 WebRTC；音訊是播放主時鐘

目前最重要的耦合：影格已含拍攝背景，VideoFrame.from_ndarray(..., format="bgr24") 輸出的是完整不透明畫面；舞台的 CSS 背景放在 video 後面，無法透過改 CSS 換掉影格中的綠幕。

03 / Gap analysis

原始需求與修改前的差距

希望做到目前狀態需要新增的能力
上傳綠幕影片建立數位人能上傳影片並抽幀；原綠幕會留在完整影格內。匯入時產生與保留影格逐幀對齊的全身 alpha／foreground；去綠邊與品質檢查。
控制台隨意換背景舞台設定只有字幕、看板、麥克風布局；沒有背景素材、選取或合成設定。背景素材庫、場景設定 API、預載與原子套用、圖片／影片時間軸。
換角色不動背景角色與原背景合在同一張影格，換人等於連背景一起換。角色素材只代表人物；背景屬於獨立 SceneState。
換背景不動角色沒有獨立背景層；video 輸出是不透明 BGR 影格。合成器每幀以人物 alpha 疊到新背景，不重新建立嘴型引擎。
多角色按項目接力ServerState 只有一組全域 model/avatar；每條連線在 /offer 綁定一個角色。角色目錄與項目／任務綁定、角色資源管理、會話內可切換的渲染來源。
無縫轉場有連線時 /api/avatar 回 409；現有 transition 只處理單角色嘴型／待機。預載目標、輪次邊界切換、人物層淡接、同一音訊／視訊 track 持續輸出。
04 / Proposed architecture

建議：人物素材、場景與會話分離

建議保留現有 MuseTalk 嘴型流程，新增「整個人物的透明素材」和位於 WebRTC 輸出前的場景合成層。控制台與獨立舞台仍各有一條 WebRTC 會話，但應讀取同一份有版本的場景狀態，各自接收一致的合成畫面；錄影也能沿用輸出影格。

A / 製作期綠幕原片

上傳、檢查人臉與畫質；保留來源及版本資訊。

A / 製作期角色嘴型素材

維持 latents、臉框、嘴型 mask 與完整影格對齊。

A / 製作期人物 alpha 素材

逐幀全身去背，頭髮、手部與綠邊處理；與保留影格同索引。

B / 執行期角色提供者

依選中角色生成說話或待機人物影格；目標角色可預載。

B / 執行期SceneState

background_id 與 avatar_id 各自儲存；由控制台與舞台共讀場景版本，可另有項目／任務設定。

B / 執行期背景素材

圖片或循環影片；預先解碼並按輸出尺寸裁切。

C / 合成與輸出背景 +（人物 RGB × 全身 alpha）→ 單一完整影格 → 持續的 WebRTC video track

嘴型 mask 仍只負責嘴部；全身 alpha 負責人物與背景分離。切換時只更改指定狀態，場景合成器持續出幀。

為什麼建議後端合成：目前前端接收單一不透明 WebRTC video，控制台與舞台各有頁面。後端合成較容易讓兩者畫面、錄影與轉場一致。若日後選擇瀏覽器分層合成，也需要額外傳輸人物 alpha，並同步兩個介面。

05 / Seamless handoff

多數位人轉場應如何發生

目標是「畫面不黑、聲音不中斷連線、舊角色的回覆不混進新角色」。安全切換點建議選在對話輪次完成且尾音保護結束後；若必須中途換人，要把那次輪次明確取消並守住現有 generation fence。

1. 選定目標

依控制台或項目規則選 avatar_id；背景 ID 保持原值。

2. 預載與檢查

載入目標素材、alpha、引擎與聲音設定；確認 GPU 預算。

3. 等候安全點

本輪最後音訊幀與尾音保護完成；鎖定下一輪角色設定。

4. 視覺接力

相同背景上只對人物層做短淡接；不更換 WebRTC track。

5. 原子提交

新角色負責下一輪知識、Prompt、TTS 與影格；失敗則維持舊角色。

狀態模型

SceneState = { version, background_id, active_avatar_id, transition }

AvatarProfile = { avatar_id, engine, assets, voice, prompt, knowledge_scope, project_ids }

這是建議資料模型，不是目前已存在的類別。場景由相關的控制台與舞台共用；若有多個項目，需按項目或演播場景隔離。知識庫已有按 avatar_id 分開設定的基礎。

轉場約束
  • 角色 A → B：背景保持同一版本；字幕／音訊仍按輪次歸屬。
  • 背景 X → Y：角色與嘴型推理維持；先預載背景再切換。
  • 若目標素材載入失敗，繼續播舊角色，不顯示黑畫面。
  • 音訊仍是主時鐘；人物淡接不得阻塞音訊或累積影格。

效能取捨：同時保留兩位角色的模型與素材可能增加顯存和記憶體。先以同一 MuseTalk 引擎內多角色為第一階段，重用模型權重並限制預載角色數；跨引擎接力需另外測量預熱時間與資源峰值。

06 / Implementation map

將來實作時的切入順序

階段 1 / 素材

綠幕建立角色

在匯入流程增加全身去背，輸出與保留影格一一對應的 alpha；檢查漏綠、手部、頭髮、邊緣及幀數。舊角色可標記為「無透明素材」，避免宣稱其能換背景。

主要位置：src/avatars/builder.py、src/avatars/musetalk/avatar.py、角色資料格式。
階段 2 / 場景

背景庫與合成器

加入背景上傳、驗證、縮放、預載及場景設定。控制台與舞台共用同一個已合成的畫面；背景更換不得重建 Avatar 或中斷連線。

主要位置：src/server/runtime_settings.py、設定 routes、BaseAvatar.process_frames() 前後的媒體邊界、控制台／舞台 UI。
階段 3 / 接力

會話內切換角色

把目前全域單一角色改為可選角色來源；預載下一位，於輪次邊界原子切換，對人物層做轉場並保持同一 WebRTC track。

主要位置：src/server/state.py、routes/webrtc.py、voice_session.py、Avatar 工廠與控制台。

驗收時要看到的結果

  • 綠幕建立後，待機與說話影格都能在不同背景上顯示，沒有明顯綠邊或人物缺口。
  • 切角色時背景 ID、畫面尺寸與 WebRTC 連線不變；切背景時角色 ID、聲音、口型進度不變。
  • 連續多輪對話中，舊輪次的文字、音訊、影格不會在新角色下出現。
  • 控制台、獨立舞台與錄影呈現相同場景，背景影片循環與音訊主時鐘不互相拖慢。
  • 轉場失敗時仍可正常與原角色對話；量測首音、A/V 偏差、媒體佇列與顯存峰值。

Wav2Lip 在本專案的標示為 Research / Non-commercial；素材、模型、聲音、背景影片也需各自確認授權。這份分析沒有把其他引擎視為已支援透明人物或無縫接力。

07 / Traceability

程式碼依據

以下連結指向此儲存庫的目前來源。架構圖是整理與推論；具體行為可由連結核對。

  1. 控制台匯入與切換：importCharacter、applyAvatar。
  2. 設定 API：set_avatar、import_avatar。
  3. 匯入工作：活躍會話限制與背景工作執行。
  4. 角色素材製作：完整影格、臉框、嘴型 mask 與 latents。
  5. MuseTalk 載入與嘴型推理：原影格貼回與素材讀取。
  6. 背景庫與場景合成器：背景解碼、循環、色鍵與切換。
  7. 媒體影格輸出：process_frames 建立 BGR VideoFrame。
  8. 套用角色與舞台設定：活躍會話 409、全域角色更新、舞台設定欄位。
  9. WebRTC /offer：每個會話建立 Avatar、VoiceTurnSession 與媒體 tracks。
  10. ServerState：目前單一全域 model/avatar 與會話表。
  11. 語音輪次：STT、檢索、LLM、TTS、輪次隔離。
  12. 角色知識範圍：依 avatar_id 的知識庫設定。
  13. 獨立舞台：單一 WebRTC video、舞台背景與疊加 UI。
  14. 目前專案基線：已驗證主力組合與音訊主時鐘。
  15. 第三方授權：引擎與素材授權邊界。
