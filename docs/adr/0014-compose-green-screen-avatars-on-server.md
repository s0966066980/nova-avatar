# 在後端合成綠幕數位人與演播場景背景

控制台與獨立舞台目前各有 WebRTC 會話，接收的是不透明的完整影格。新建立的綠幕 MuseTalk 數位人將由後端把綠幕轉成人物透明度，與共用演播場景選定的靜態圖片、循環影片或 GIF 背景合成，再交給各會話原有的視訊輸出；背景選擇獨立於數位人選擇，說話中也能開始切換背景。這使兩個觀看端與錄影使用一致的場景結果，同時保留現有音訊主時鐘與輪次隔離。

瀏覽器分層合成是另一個可行方向，但目前 WebRTC 視訊不攜帶人物透明度，兩個頁面需要各自取得並同步遮罩、背景影格與切換狀態，因此這次選擇後端合成。綠幕色鍵仍需處理人物邊緣與綠色溢色；它不等於省略去背。

## Implementation Status — 2026-09-25

- 控制台建立 MuseTalk 數位人時可勾選綠幕；新角色保留 `source.*` 原片，`avator_info.json` 記錄 Nova Avatar 來源與相對路徑。既有 `musetalk_avatar` 作為綠幕試用素材，其他舊角色不自動套用色鍵。
- 背景支援 JPG／PNG／WebP、循環 MP4／MOV／WebM 與 GIF，存放於 `data/backgrounds/`，由 `src/scene/service.py` 在 Avatar 渲染執行緒外解碼。控制台與獨立舞台讀取同一個 `background_id`，與 `avatar_id` 各自持久化。
- MuseTalk 完成嘴型後才執行色鍵、邊緣去綠光與背景合成，再交給 WebRTC 與錄影。講話中切換背景時先載入新背景，再約 0.2 秒淡接，不重建數位人或 WebRTC 會話。
- 控制台未連線時顯示合成的靜態預覽。刪除非使用中的角色或背景會移至 `data/avatars/.deleted/`、`data/backgrounds/.deleted/`，可在控制台復原；封存角色可在確認後永久刪除。

## 已知限制與後續

- 目前依綠色差值即時計算柔邊，尚未保存逐幀全身 alpha；綠色衣物、髮絲與邊緣品質仍需實測。原片內嵌文字屬影格像素，色鍵不會移除。
- 切換數位人仍須斷開會話（有活躍會話時 `/api/avatar` 回 409）。跨角色不斷線轉場需要預載目標角色、在輪次邊界原子切換、只對人物層淡接並保持同一 WebRTC track，屬於尚未排程的後續工作。
- 背景影片、圖片與綠幕原片的授權需各自確認，不因本合成功能而包含於根目錄 Apache-2.0。
