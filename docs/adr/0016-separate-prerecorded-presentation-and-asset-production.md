# 將預錄呈現與說話素材製作分離

Jetson 的高解析背景合成與編碼成本不會隨嘴型推論移除而消失，因此
預錄呈現由觀看端瀏覽器播放待機／說話素材、執行綠幕合成並錄製該端
場景；伺服器繼續擁有回答語音與對話輪次。控制台的說話素材錄製則
使用 MuseTalk 離線製作完整品質、無音軌、保留綠幕的五秒影片，預錄
模式日常啟動與對話不載入或預熱嘴型模型。

## 責任與代價

- 本決策調整 [ADR-0014](0014-compose-green-screen-avatars-on-server.md)
  在預錄呈現下的場景合成與錄影責任；MuseTalk 即時呈現仍使用原有
  伺服器合成路徑。兩種呈現方式共用角色、舞台背景與對話規則。
- [ADR-0001](0001-push-avatar-speaking-state-over-webrtc.md) 的伺服器
  發話權威與 [ADR-0007](0007-stream-replies-with-turn-isolation-and-audio-clock.md)
  的輪次隔離／音訊主時鐘仍適用。素材切換須對齊接收端語音，伺服器
  事件到達時間不等同於使用者聽到語音的時間。
- 預錄會話保留一條 64×32 的 WebRTC 時鐘影像軌。伺服器在 RTP
  實際出幀時把媒體毫秒編入影格，瀏覽器使用與語音同步解碼的時鐘
  消費 `presentation_activity`，並使用音訊與視訊的
  `estimatedPlayoutTimestamp` 差值修正實際接收端播放差，包含初始
  抖動緩衝。此值來自 RTCP 的共同 NTP 時鐘，參照
  [W3C WebRTC Statistics](https://www.w3.org/TR/webrtc-stats/#dom-rtcinboundrtpstreamstats-estimatedplayouttimestamp)。
  首次時鐘就緒前維持待機；無法取得時鐘會明示錯誤並保留語音。
  事件依實際輸出 PCM 的有效音量邊緣產生，保留輪次與 generation
  隔離；此軌只承載時序，人物高解析像素由本機影片產生。
- 瀏覽器需要承擔影片解碼、去背、場景合成與錄影編碼；錄影頁面必須
  保持開啟且在前景。錄影格式支援與雙畫面效能需在目標裝置實測，
  本決策不代表已達成 1080×1920／25 fps。
- 說話素材製作允許超過五秒等待；影片本身固定五秒，不繼承即時
  產幀卡頓。所有會話斷線後單工製作，完成、取消或失敗都釋放
  嘴型資源。素材先預覽，明確套用後才替換，保留上一版供還原。
- 預錄模式輸出一般對話錄影為 MP4；瀏覽器無法直接錄製此容器時
  保留原始錄影，再由 Jetson 非即時轉檔，不回到即時逐幀傳輸。

## 考慮的替代方案

- 伺服器逐幀播放預錄影片並沿用既有合成與錄影：接入較小，但仍保留
  各會話的高解析合成與即時編碼，已有微基準顯示該成本可能超過
  25 fps 預算，故不作為預錄模式的主要播放路徑。
- 直接從正在播放的 MuseTalk 畫面錄五秒：會包含舞台背景、輸出
  縮放與即時產幀不足，無法保證可重用的綠幕素材與固定影片時長。

## 2026-10-13 操作修正

預錄合成尺寸採素材原始尺寸，MuseTalk 的 `video.max_height` 僅影響
即時模式。切換使用明確套用操作，可選擇結束當前對話並自動重連
控制台與舞台。GPU 重載在背景執行，獨占鎖持續到工作完成；取消
HTTP 請求不會提前釋放鎖。素材製作與套用仍要求會話斷線。

會話以頁面識別與 presenter 隔離，失敗或取消的協商會清理名額與
媒體管線。同頁重連會替換舊會話；跨 presenter 的名額保持獨立。
區網預設使用主機 ICE 候選，外部 STUN 改為明確設定。語音準備
與協商平行，收音 gate 在準備完成前保持關閉；純觀看不載入 STT。

接收端 RTCP 時鐘若晚到或暫時中斷，保留待機與語音並持續校準，
恢復後解除等待；不將暫時缺少時序資訊記為不可恢復的媒體錯誤。
舞台自動重連保留使用者的收音暫停選擇。
切換、下載與雙畫面實測見 [操作修正驗證](../../.scratch/prerecorded-avatar/fixes/README.md)。
