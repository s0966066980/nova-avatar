# 由各場對話持有分析附件

控制台與數字人舞台新增的 PDF／圖片分析，使用目前場次持有的「對話附件」，供該場提問及後續追問；檔案不自動成為永久知識庫文件。這是在 2026-10-27 訪談 Q2 已確認的資料邊界，讓臨時訪客檔案與管理者持續維護的知識範圍各有生命週期，也避免把單場分析意外變成共用資料。

此決策補充 [ADR 0013](0013-use-ragflow-for-retrieval-only.md)：既有 RAGFlow 文件管理與檢索維持各自責任；聊天室新增的是場次附件分析入口。Q8、Q12、Q13 已確認所有舞台採兩層清除：3 秒閒置只清回答字幕與看板，120 秒閒置才完整清空記憶、附件與草稿，保留語系、聲音及外觀。兩個計時從最後一次操作或回答完成起算，上傳、分析與回答期間暫停；控制台維持手動清空。

Q17、Q18 後續確認附件不因歷史則數淘汰而刪除，可逐輪選用；失敗或取消保留問題與可重用附件，取消後停止未交付輸出。Q21、Q22 確認同頁短暫斷線可保留未送本機草稿，但已送附件不轉移到新場次；刷新或關頁不復原。附件可個別移除，原檔及衍生快取刪除後停止後續引用，既有回覆及歷史文字不回溯改寫。

使用者於 2026-10-28 在 Q25 明確確認「是，開始實作」。實作使用已核對的 Gemma 4 配對視覺權重、PDFium 及本機 Tesseract OCR；已驗證代表性圖表、繁中／英文文件與舞台流程，長文件數字彙整仍有模型品質限制，不能視為任意文件的全面正確性保證。使用與限制見[對話附件文件](../conversation-attachments.md)，完整確認及驗收紀錄見[功能規格](../../.scratch/conversation-attachments/spec.md)。
