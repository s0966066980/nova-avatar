# 將閒置招呼與訪客提問分開編排

既有文字與固定詞入口會建立一般訪客對話輪次；直接套用到循環招呼，會把主動招呼當作訪客問題、在內容準備時暫停收音，並反覆累積對話記憶。因此閒置招呼採獨立於訪客提問的發話來源，由伺服器協調；準備期間保留收音並讓訪客互動優先，正式播放才沿用既有收音閘門、插話、實際播放提交與角色媒體隔離。

只保留最近一次已播招呼供後續追問，招呼生成使用主角色身分與管理者的生成指令，不使用訪客記憶、檢索或交接路由。招呼不觸發或延後訪客對話重置；上一場對話先清場、回主角色，再容許招呼開始準備，避免自動播放無限延長上一位訪客的會話。

此邊界已由獨立招呼控制器、內容生成與實際播放提交實作；詳細需求與驗收條件見[閒置招呼規格](../../.scratch/idle-greeting/spec.md)。既有伺服器輪次編排與已播內容提交保證繼續適用。

操作方式與試播限制見[使用說明](../idle-greetings.md)。
