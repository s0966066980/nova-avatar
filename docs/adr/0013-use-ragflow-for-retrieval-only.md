# 以獨立 RAGFlow 服務提供檢索，不接管回答

Nova Avatar 要讓數位人使用管理者提供的文件，同時維持現有模型、回覆規則、語音與看板的回答契約。RAGFlow 在目前主機上作為獨立 Docker 服務運行，只提供知識庫檢索；Nova Avatar 仍負責產生及播放回答。管理者在 RAGFlow 介面上傳文件，Nova 控制台負責啟用、選擇知識庫、測試檢索與顯示連線狀態。RAGFlow API 金鑰由伺服器端設定，不經現有未驗證的控制台設定 API。

2026-09-17 啟動流程修訂：RAGFlow 仍使用獨立 Compose 專案與資料卷；主機完成
`scripts/ragflow.sh prepare` 後，`scripts/start-all.sh` 會協調啟動。
它只在自己帶起服務時於結束時停止 RAGFlow；原本在執行的實例維持原生命週期。

同一套 RAGFlow 服務可供多個數位人使用，但每個數位人的檢索啟用狀態與知識庫選擇分別保存。目前只有一位數位人，也維持此邊界，避免未來加入角色時共用錯誤的文件範圍。語音與控制台文字發問都採相同的檢索輔助回答流程；文件以中英混合為預設情境，嵌入模型在本機運行，文件不送往外部嵌入 API。

## Considered Options

- 由 RAGFlow 聊天助手直接回答：會改變既有模型規則、看板協定與已播回覆的責任邊界，因此不採用。
- 在 Nova 控制台複製文件管理功能：第一階段不採用，文件上傳與解析由 RAGFlow 自帶介面處理。
- 以其他主機承載 RAGFlow：可隔離主機資源，但本次決定部署在目前主機，並以獨立服務隔離生命週期及資料。

## Consequences

- 檢索內容只能輔助目前對話輪次，不能作為已播回覆或使用者訊息提交。
- 同機部署仍會共用 CPU、記憶體及磁碟；服務隔離不等於硬體資源隔離。
- 安裝時依使用者補充，RAGFlow 的 BGE-M3 嵌入端點使用主機已安裝的 Ollama 程式與模型檔，另啟 CPU 程序；Nova 現有 Ollama／llama.cpp 語言模型服務不改動。不拉取新的 Ollama 容器映像。
- RAGFlow 不可用時，數位人繼續使用原本模型回答，控制台標示檢索失敗；沒有命中內容時也允許一般回答，但必須標明沒有文件依據。
- 沒有命中內容的說明需同時出現在數位人的回答與控制台；不得把一般知識回答表示成有知識庫支持。
- 控制台可列出檢索參考；不得將檢索片段當成模型已引用的正式引文，也不得直接放進語音或看板項目。
- RAGFlow 管理介面第一階段只允許本機存取。文件解析與查詢應優先保護既有對話效能，部署後需量測資源占用與對話延遲。
- 角色切換後不得沿用前一位數位人的知識庫選擇或尚未完成的檢索結果。
- 每位數位人的知識庫選擇是回答行為的分流，並非使用者權限隔離；現有控制台沒有角色授權機制。

## 修訂 — 2026-09-21

- 嵌入程序改用 GPU：預設 CUDA 裝置 0，可用 `NOVA_RAGFLOW_CUDA_VISIBLE_DEVICES` 覆寫；仍是獨立於 Nova 語言模型服務的 Ollama 程序。上文「另啟 CPU 程序」為原始決策記錄。
- 沒有命中時不再於語音或控制台對話加註「知識庫沒有找到相關資料」；模型照常一般回答，檢索狀態只保留在 `rag_retrieval` 事件。服務不可用時控制台仍標示失敗，也仍不得把一般回答表示成有知識庫依據。
